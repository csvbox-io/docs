A destination is where the importer pushes the data your users upload. You choose it per sheet in the sheet settings, and CSVbox delivers every validated import there automatically.

<Note>
  Only one destination can be selected per sheet at a time.
</Note>

## None

The user-uploaded data isn't pushed anywhere. The files are, however, available for download via the CSVbox admin.

## Test API

A lightweight destination that helps you validate your CSVbox setup quickly, before wiring up your own backend.

When selected, every successful import posts the parsed spreadsheet data to a **unique HTTPS URL** hosted at [https://webhooks.csvbox.io/](https://webhooks.csvbox.io/). Example:

```html
https://webhooks.csvbox.io/b/5f3b0901-1c32-4d83-9fdd-a454e56e1938
```

Use it to confirm payload shape, headers, and delivery behavior during initial integration.

<Warning>
  The Test API is designed **for initial testing only**. Do not use it for production data flows.
</Warning>

### When to use it

- You're integrating CSVbox for the first time and want to **see the JSON** CSVbox sends.
- You need to **confirm columns, data types, and null handling** after the mapper and validators run.
- You want a **no-setup** endpoint to verify end-to-end delivery before connecting your real destination.

## API / Webhook

The data is pushed to a webhook endpoint configured in the sheet settings. You can receive the data at your webhook as JSON, XML, or FORM Data.

The data is pushed in chunks of rows. You can configure the number of rows per chunk in the sheet settings.

### Sample JSON POST to your API

```javascript
[
  {
    "import_id": 79418895,
    "sheet_id": 55,
    "sheet_name": "Products",
    "row_number": 1,
    "total_rows": 5,
    "env_name": "default", 
    "original_filename": "products01_24.csv",
    "row_data": {
          "Name": "TP-Link TL-WN822N Wireless N300 High Gain USB Adapter",
          "SKU": "AS-100221",
          "Price": "33.00",
          "Quantity": "3",
          "Image URL": "https://cdn.shopify.com/s/files/1/1491/9536/products/31jJOj1DS5L_070b4893-b7af-482f-8a15-d40f5e06760d.jpg?v=1521803806"
    },
    "custom_fields": {
      "user_id": "1a2b3c4d5e6f",
      "team_id": "sales2"
    }
  },
  {
    "import_id": 79418895,
    "sheet_id": 55,
    "sheet_name": "Products",
    "row_number": 2,
    "total_rows": 5,
    "env_name": "default", 
    "original_filename": "products01_24.csv",
    "row_data":{
          "Name": "EPower Technology EP-600PM Power Supply 600W ATX12V 2.3 Single 120mm Cooling Fan Bare",
          "SKU": "AS-103824",
          "Price": "95.35",
          "Quantity": "8",
          "Image URL": "https://cdn.shopify.com/s/files/1/1491/9536/products/71pRC5VjF-L_8f840eb9-6a47-407f-999c-490f7814159d.jpg?v=1521803806"
        },
    "custom_fields": {
      "user_id": "1a2b3c4d5e6f",
      "team_id": "sales2"
    }
  },
]
```

<Note>
  The data arrives as HTTP POST requests. Each request contains an array of rows based on the chunk size defined in the sheet settings. Set the chunk size to 1 to receive one record per HTTP request.

  If the row count is greater than 10,000, the chunk size defaults to 1000. A large row count with a small chunk size increases the processing time significantly.
</Note>

### Request type

The webhook can be called in two modes to push the data to the destination:

- **Sequential**: webhook APIs are invoked in sequential order, one after another.
- **Parallel** (default): multiple webhook APIs are invoked concurrently, so your application receives chunks of rows in parallel. This reduces overall import time. However, your application needs to manage the order of data based on the `row_number` attribute.

<Tip>
  To get started quickly, test with [webhook.site](https://webhook.site) to get a webhook URL. For testing on your local machine, use [ngrok](https://ngrok.com/).
</Tip>

## Amazon S3

The files your users upload can be pushed to the AWS S3 bucket of your choice. Select **Amazon S3** as the destination type and provide the AWS credentials, the bucket/folder name, and the access policy for storing the files.

<Note>
  The data is stored as S3 objects named `{{import_id}}_{{user_id}}.csv`, where `user_id` is the custom user attribute you reference via the `setUser` method while installing the importer code. The other 4 custom user attributes are saved as the [user-defined metadata](https://docs.aws.amazon.com/AmazonS3/latest/userguide/UsingMetadata.html) of the S3 object.
</Note>

The AWS credentials need the following 3 minimum policies for uploading files to S3:

- `ListBucket`: required for testing the connection.
- `PutObject`: required to add objects to S3.
- `PutObjectTagging`: required to add the tags (metadata) to the uploaded objects.

### S3 data type

You can store the data in S3 in either CSV or JSON format.

## FTP Server

The files your users upload can be pushed to your FTP server. Select **FTP** as the destination type and provide the connection details and the folder name for storing the files.

<Note>
  The data is stored as CSV files named `{{import_id}}_{{user_id}}.csv`, where `user_id` is the custom user attribute you reference via the `setUser` method while installing the importer code.
</Note>

## SQL Server

Import CSV files and Excel sheets directly into your SQL Server tables.

<Steps>
  <Step title="Select SQL Server as the destination">
    Select **SQL Server Database** as the destination type.
  </Step>
  <Step title="Connect your database">
    Connect your SQL Server database by providing the credentials.
  </Step>
  <Step title="Set the target table">
    Specify the table name where you want the data to be pushed.
  </Step>
  <Step title="Test the connection">
    Click **Test Connection**.
  </Step>
  <Step title="Map columns">
    If the connection is successful, click **Map Columns** and match the sheet template columns to the SQL Server table columns. You can also map custom attributes to table columns.
  </Step>
  <Step title="Choose the operation">
    Select one of the following 2 operations:

    - **Insert**: the importer always pushes the incoming CSV data as new records in the database.
    - **Upsert**: the importer checks whether the record exists in the database. If it exists, it's updated with the incoming data from the CSV. If it doesn't, a new record is inserted. The record check is based on the index keys specified in the mapping modal.

    <Frame>
      <img
        src="/images/unique-1.jpg"
        alt="Define unique key for upsert operation"
      />
    </Frame>
  </Step>
</Steps>

<Warning>
  The **Upsert** operation is significantly slower than the **Insert** operation. With **Insert**, records can be pushed in chunks, whereas **Upsert** processes only one record at a time and requires multiple queries.
</Warning>

## MongoDB

Import CSV files or Excel sheets into your MongoDB collections.

<Steps>
  <Step title="Choose MongoDB as the destination">
    Select **MongoDB** as your destination type.
  </Step>
  <Step title="Connect your database">
    Enter your MongoDB credentials to establish a secure connection.
  </Step>
  <Step title="Set the target collection">
    Specify the name of the collection where the data should be inserted.
  </Step>
  <Step title="Map columns to fields">
    Match the columns in your sheet to the corresponding fields in your MongoDB collection.
  </Step>
  <Step title="Define field data types">
    Assign appropriate data types to each field to ensure accurate data import.
  </Step>
  <Step title="Map custom attributes (optional)">
    You can also map custom attributes from the CSV to specific fields in your collection.
  </Step>
</Steps>

Once set up, all submitted CSV data is automatically inserted into your MongoDB collection.

  The data fields from Airtable are available in the Map Column modal only if they have **data in the first row**. Add dummy data for each data field in the first row so that they appear in the Map Column modal.
</Warning>

### Operations

There are 2 operations available for Airtable.

#### 1. Insert

Creates a new row in the table.

#### 2. Upsert

Updates an existing row if a specified value already exists in the table, and inserts a new row if it doesn't. Select the column to check for uniqueness in the **Column Mapping** popup.

<Frame>
  <img
    src="/images/upset-airtable.jpg"
    alt="Select the unique column for an Airtable upsert"
  />
</Frame>

- If zero matches are found, a new row is created.
- If one match is found, that row is updated.
- **If multiple matches are found, the request fails.**
