## Server & data location

Select the geographic location of the servers and database for the user data.

Data residency refers to the geographical location where data is stored. The location is usually important for regulatory or policy reasons. You can select the storage location of the data uploaded by your users.

Go to **Edit Sheets** → **Options** → **Privacy & Security** section and select the location from the dropdown.

<Frame>
  <img
    src="/images/locations.png"
    alt="Data location dropdown in Privacy & Security settings"
  />
</Frame>

The US is the default location. The other option is Europe (Germany). The data uploaded by users then passes through servers and is stored in the database situated in the selected location only.

<Note>
  You also have the option to not store the data at all.
</Note>

The long-lived data about the import and the user files isn't covered by the selected location. It mainly consists of supplementary log data that helps with troubleshooting and analyzing the import processes. This data doesn't include any original data from inside the user files.

The image below shows how the data flows if you select Europe as the data residency location.

## Domain authorization

Run the importer on select domains only.

Provide a list of authorized _domains/sub-domains_ for embedding the importer. The embedded importer works on the whitelisted domains only.

Go to **Edit Sheets** → **Options** → **Authorized Domains** and add the domains/subdomains.

<Frame>
  <img
    src="/images/domains.jpg"
    alt="Authorized Domains setting"
  />
</Frame>

- If you don't whitelist any domain, the importer embed works on all domains. This is the default configuration.
- You can use the `*` wildcard prefix to include any subdomain. A few examples:

| Text | Valid | Invalid |
| --- | --- | --- |
| `exampleco.com` | `exampleco.com` | `www.exampleco.com`, `app.exampleco.com` |
| `www.exampleco.com` | `www.exampleco.com` | `exampleco.com`, `app.exampleco.com` |
| `app.exampleco.com` | `app.exampleco.com` | `exampleco.com`, `www.exampleco.com` |
| `*.exampleco.com` | All `exampleco.com` subdomains |  |

## Zero template columns

Accept file submissions without requiring any predefined template columns.

This is useful when you want users to upload files with their own structure, without enforcing a strict column format.

### How it works

- By default, CSVbox requires at least one template column for mapping.
- Setting **Allow Zero Template Columns** to **Yes** lets users submit files **without any predefined template columns**, providing complete flexibility.
- You can combine this setting with the [Unmapped Columns](/advanced-installation/unmapped-columns) feature, so users can upload files with **any set of columns** without a predefined template structure.

<Frame>
  <img
    src="/images/sleekshot-5.png"
    alt="Allow Zero Template Columns setting"
  />
</Frame>

### When to use this feature

- When you want to **fully accommodate user-defined file formats**.
- When you prefer **not to enforce a rigid template**, giving users the freedom to submit files as they are.

<Note>
  For this feature to work effectively, set **Allow Unmapped Columns** to **Yes** along with the **Show Unmapped Columns on Validation Screen** selection. This lets users review and verify file columns before submission.
</Note>

## Formatting in Excel files

Handle Excel file formatting for dates, times, and numbers.

When importing data from Excel files, you may run into unexpected issues because of the way Excel internally stores and formats values, especially **Dates**, **Times**, and **Numbers**. Unlike CSV files, Excel files can retain formatting, formulas, and cell types, which can lead to inconsistencies or misinterpretation during import.

To give you better control over how your data is interpreted, CSVbox provides customizable options to configure how Excel data is processed.

<Note>
  To handle dates and numbers written in different regional styles in an uploaded file (for example a day-first `04/05/2024` or a European `1.234,56`), see [Smart Date and Number Formats](/dashboard-settings/smart-date-and-number-formats).
</Note>

### Date formatting issues in Excel

Excel stores dates in one of two ways:

- **As formatted text**: e.g., `"03/04/2024"`
- **As numeric serial values**: e.g., `45025`, which represents the number of days since January 1, 1900.

This dual nature can lead to problems during import, especially with international date formats. For example:

- `"03/04/2024"` might be **March 4** in the U.S. (MM/DD/YYYY)
- ...or **April 3** in Europe (DD/MM/YYYY)

If Excel stores the date as a number (`45025`) and the importer misinterprets the format, the final result could be completely off. To address this, CSVbox lets you explicitly define how Excel date values are interpreted.

#### Date handling options

- **Default**: Uses Excel's built-in logic to interpret the cell as a date. Best for files with consistent formatting and locale.
- **MM/DD/YYYY**: Forces interpretation using the **Month-Day-Year** format. Example: `"03/04/2024"` → March 4, 2024
- **DD/MM/YYYY**: Forces interpretation using the **Day-Month-Year** format. Example: `"03/04/2024"` → April 3, 2024
- **Custom**: Define a custom format like `YYYY-MM-DD`, `DD-MMM-YYYY`, or any other pattern based on how your Excel file stores the date. Example: `"12-Mar-2024"` → use custom format `DD-MMM-YYYY`

<Tip>
  If your dates are inconsistently formatted or include a mix of text and numeric formats, consider cleaning them in Excel first, or use the **Custom** option for better accuracy.
</Tip>

### Time formatting issues in Excel

Excel also stores time values either as:

- **Numeric fractions** of a day (e.g., `0.5` represents 12:00 PM)
- **Formatted time strings** (e.g., `"14:30"`, `"2:30 PM"`, `"14:30:00"`)

This can create parsing issues, especially if some cells are stored as numbers and others as formatted text. For example:

- `0.75` → might mean `6:00 PM` (75% of a day)
- `"06:00"` → clearly indicates 6 AM, but may be read as a string

To avoid misinterpretation, CSVbox provides the following options.

#### Time handling options

- **Default**: Uses Excel's formatting as-is. Suitable for simple, clean files.
- **HH:MM:SS**: Example: `"14:30:00"` → 2:30 PM
- **HH:MM AM/PM**: Example: `"2:30 PM"` → 14:30
- **Custom**: Define your own time pattern like `HH:mm`, `h:mm a`, etc., based on your file's content.

### Number formatting issues in Excel

Excel often applies formatting to numeric values that changes how they appear:

- A raw value of `0.15` could be displayed as `15%`
- A value of `1200` might appear as `$1,200.00`
- A long number like `1234567890123` may be auto-converted to scientific notation (`1.23E+12`)

These formatted displays can mislead the importer if you're expecting clean numbers.

#### Number interpretation options

- **Formatted Values**: Imports numbers exactly as shown in Excel. Examples:
  - `$1,200.00` stays `$1,200.00`
  - `15%` stays `15%`
  - `1.23E+12` stays in scientific notation
- **Original RAW Values**: Strips all formatting and imports the core numeric value. Examples:
  - `$1,200.00` → `1200`
  - `15%` → `0.15`
  - `1.23E+12` → `1230000000000`

<Tip>
  Use RAW if you're planning to run calculations or validations on numeric fields post-import.
</Tip>

### How to use these settings

#### Configure date formatting

When setting up your Excel-based import:

<Steps>
  <Step title="Open the File Upload tab">
    Go to **Sheet Settings** → **Import Steps** → **File Upload** tab in your CSVbox dashboard.
  </Step>
  <Step title="Find the Excel formatting section">
    Scroll to the **Formatting in Excel** section.
  </Step>
  <Step title="Choose a date format">
    Choose your preferred option for **Date Format**.
  </Step>
  <Step title="Save the configuration">
    Save the configuration.
  </Step>
</Steps>

#### Configure number formatting

To control how numbers are interpreted from Excel files:

<Steps>
  <Step title="Open the columns">
    Go to **Sheet Settings** → **Columns**.
  </Step>
  <Step title="Edit a Number column">
    Click **Edit** on a column with type **Number**.
  </Step>
  <Step title="Select a Values for Excel setting">
    Locate the **Values for Excel** option and select your preferred interpretation setting.
  </Step>
  <Step title="Save the configuration">
    Save the configuration.
  </Step>
</Steps>

#### Notes

- Date formatting is configured at the **sheet level during file upload setup**.
- Number formatting is controlled at the **individual column level**, allowing more granular control per field.

These controls make sure your data is interpreted as intended, minimizing errors and reducing the need for pre-processing in Excel before importing.

## Sheet import & export

Export a sheet from one CSVbox account and import it into another account, or duplicate it within the same account, in just a few clicks.

This is perfect for:

- Moving sheets between staging and production accounts
- Sharing templates across teams
- Backing up sheet configurations
- Reusing validated sheet structures

### Export a sheet

<Steps>
  <Step title="Open your sheets">
    Go to **Sheets** in your dashboard and locate the sheet you want to export.
  </Step>
  <Step title="Click Export">
    Click the **Export** button in the **Actions** column. A dialog opens showing:

    - **Sheet License Key**
    - **Export Key**
    - Options to **Copy**, **Show**, or **Regenerate** the export key.
  </Step>
  <Step title="Copy both keys">
    Copy both the **Sheet License Key** and the **Export Key**.
  </Step>
</Steps>

### Import a sheet

<Steps>
  <Step title="Log in to the target account">
    Log in to the account where you want to import the sheet.
  </Step>
  <Step title="Choose Import Sheet">
    Click **Add Sheet**, then select **Import Sheet**.
  </Step>
  <Step title="Paste the keys">
    Paste the **Sheet License Key** and the **Export Key**.
  </Step>
  <Step title="Click Import">
    Click **Import**. The entire sheet, including columns, validations, configuration, and settings, is copied into the new account.
  </Step>
</Steps>

### Important

- The newly imported sheet has a **new License Key**.
- The original sheet remains unchanged.
- Importing does **not** affect existing imports or data in the original sheet.
