Validations check every incoming value against the rules you set for its column. When data doesn't match, users see an error message that explains the problem and how to fix it, so only clean data reaches your destination.

## Column data types

While creating a sheet, you can set each column to any of the data types below. If the incoming CSV data doesn't match the column data type (and its validation rules), the user sees an error message identifying the problem and how to fix it.

### Text

This is the default column data type. It accepts any alphanumeric string. Use the `Min Length` and `Max Length` parameters to specify the acceptable length of the text data.

### UUID

The column must contain a valid UUID.

### Number

The **Number** column data type accepts integer and float strings only. Use the `Min Value` and `Max Value` parameters to specify the acceptable range of numbers.

#### Values for Excel setting

When importing data from Excel files, you may run into unexpected issues because of the way Excel internally stores and formats values, especially **Numbers**. Excel often applies formatting to numeric values that changes how they appear:

- A raw value of `0.15` could be displayed as `15%`
- A value of `1200` might appear as `$1,200.00`
- A long number like `1234567890123` may be auto-converted to scientific notation (`1.23E+12`)

These formatted displays can mislead the importer if you're expecting clean numbers. CSVbox lets you choose how values are interpreted for numeric columns:

- **Formatted Values**: Imports numbers exactly as shown in Excel. Examples:
  - `$1,200.00` stays `$1,200.00`
  - `15%` stays `15%`
  - `1.23E+12` stays in scientific notation
- **Original RAW Values**: Strips all formatting and imports the core numeric value. Examples:
  - `$1,200.00` → `1200`
  - `15%` → `0.15`
  - `1.23E+12` → `1230000000000`

<Tip>
  Use RAW if you're planning to run calculations or validations on numeric fields post-import.
</Tip>

<Note>
  If your users upload files from different regions, turn on [Smart Date and Number Formats](/dashboard-settings/smart-date-and-number-formats) to handle numbers written with different thousands and decimal separators, such as `1,234.56` and `1.234,56`.
</Note>

### Percentage

The column must contain a valid **percentage** value. You can specify `Min` and `Max` values, and use the `Output` setting to control whether the percentage is stored as a value such as `50%` or `50`. Percentage values are normalized in the data worker.

### Email

The column must be formatted as an email address.

### IANA timezone

The column must contain a valid IANA timezone. CSVbox validates the timezone and normalizes timezone values during processing.

### Boolean

The column must be castable as a boolean. Accepted inputs are `true`, `false`, `TRUE`, `FALSE`, `1`, `0`, `yes`, `no`, `y`, `n`, `on`, `off`, `enabled`, and `disabled`.

<Info>
  To show this column as a checkbox on the Verify Data screen and always send `true` or `false`, see [Checkbox Display for Boolean Columns](/dashboard-settings/checkbox-boolean-columns).
</Info>

### Regex

The column data must match the given regular expression. Specify the `Regex`, and the importer pattern-matches it against the incoming data.

### JSON

The column must contain valid JSON data.

### IP

The column must be an IP address. Select the `IP Version`.

### URL

The column must be a valid URL.

### Domain

The column must contain a valid domain name.

### Credit card

The column must be formatted as a credit card number. Acceptable formats are `5555555555554444`, `5555-5555-5555-4444`, and `5555 5555 5555 4444`.

### UPC

The column must contain a valid UPC product barcode.

### EAN

The column must contain a valid EAN product barcode.

### IMEI

The column must contain a valid IMEI number.

### Phone number

The column is validated for phone number formats based on the [libphonenumber.js library](https://catamphetamine.gitlab.io/libphonenumber-js/). Select a default country code. If an incoming phone number has no country code, the default country code is used for validation.

### Currency

The column data must be in a currency amount format. You can specify currency formatting options based on the [Validator.js library](https://github.com/validatorjs/validator.js).

### Currency code

The column must contain a valid currency code.

### List

With the **List** data type, you specify a list of acceptable values. The importer compares the CSV column data with the list and throws a validation error if there's a mismatch.

You specify a list of acceptable `Values` and related `Display Labels`. The importer matches the column data with the list of `Display Labels`. If the data passes validation, the `Values` corresponding to the `Display Labels` are pushed to the destination. For example, say you configure the List column as shown below:

<Frame>

  />
</Frame>

In this case, the acceptable data in the CSV column is `Small`, `Medium`, and `Large`. Based on the actual data in the user's CSV, the values `s`, `m`, or `l` are pushed to your data destination. This lets you accept readable values from your users while pushing data in a format your system understands.

  </Step>
  <Step title="Add the dependent values">
    For each valid country value, add dependent (city) values as shown below.

    <Frame>
      <img

      />

  </Step>

</Warning>

### Dynamic list

This is similar to the **List** type above: the importer validates the column data against a list of values. However, instead of providing a static list, the **Dynamic List** column type lets you supply the list of acceptable values in real time via an API.

The API must return the list of values in the JSON format shown below.

```json
[
   {"value": "uk", "display_label": "England"},
   {"value": "us", "display_label": "United States"},
   {"value": "au", "display_label": "Australia"}
]
```

For each list item, the `value` field is mandatory, while `display_label` is optional.

You can attach the [custom user attributes](/getting-started/2-install-code#referencing-the-user) as query parameters to the Dynamic List API request. The `csvbox_` prefix is added to the custom user attribute query parameters. This helps you identify the users or environment and return a relevant list of values.

To authenticate the requests, pass the authorization headers via the [`dynamic_list_request_headers`](/getting-started/2-install-code#dynamic_list_request_headers) initialization option.

<Steps>
  <Step title="Create the primary column">
    Create a column `Country`. Set its column type to **Dynamic List**.
  </Step>
  <Step title="Create the dependent column">
    Create a column `City`. Set its column type to **Dependent Dynamic List**, and select `Country` as the **Primary** column.

    <Frame>
      <img
        src="/images/cols.png"
        alt="Dependent column with Country selected as the primary column"
      />
    </Frame>
  </Step>
  <Step title="Configure the API">
    Go back to the `Country` column and configure the API that fetches valid values from your application for `Country` as well as its dependent column, `City`. Your API must return the list of values in the JSON format shown below.

    ```json
    [
       {"value": "USA", "display_label": "USA", "dependents": [
          {"value": "ny", "display_label": "New York"},
          {"value": "ch", "display_label": "Chicago"},

          {"value": "mi", "display_label": "Miami"}

          {"value": "to", "display_label": "Toronto"},
          {"value": "va", "display_label": "Vancouver"}    
       ]}
    ]
    ```

    The `dependents` object contains the list of valid values for the dependent column based on the primary column value.
  </Step>
</Steps>

<Warning>
  - If you change the name of the primary column or reorder the priority of any of the columns, reassign the primary column in the Dependent Dynamic List column settings.
  - The Display Label and the Value must be unique across all items. Primary items can't share dependents that have the same Display Label and/or the same Value.
</Warning>

The **Multi-select List** data type is similar to the [List](/dashboard-settings/validations#list) data type: you specify a list of acceptable values. While the **List** data type accepts only one value per cell, the **Multi-select List** accepts multiple comma-separated values.

### Dynamic multi-select list

This is similar to the **Multi-select List** type above: the importer accepts multiple comma-separated values. However, instead of providing a static list, you supply the list of acceptable values in real time via an API.

The API must return the list of values in the JSON format shown below.

```json
[
   {"value": "Red"},
   {"value": "Green"},
   {"value": "Blue"}
]
```

The importer attaches the [custom user attributes](/getting-started/2-install-code#referencing-the-user) as query parameters to the Dynamic List API request. The `csvbox_` prefix is added to the custom user attribute query parameters. This helps you identify the users or environment and return a relevant list of values.

To authenticate the requests, pass the authorization headers via the [`dynamic_list_request_headers`](/getting-started/2-install-code#dynamic_list_request_headers) initialization option.

## Other validation options

### Column required

Check or uncheck the `Required` checkbox in the **Column Settings** window. When it's ticked, the column data must be present and not empty.
